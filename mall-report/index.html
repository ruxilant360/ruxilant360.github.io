Retail Centre Performance Report

A month-end report for a portfolio of three shopping centres: tenant sales against budget, foot traffic, occupancy and upcoming lease expiries. Before reporting, I ran a set of data checks that changed the story for one of the centres.

Key findings at the September 2026 close

+17.5% → −2.4%

Lakeshore's August "beat" was a data error

One tenant reported $2.05M against a normal ~$185K: a misplaced decimal. Corrected, the centre was slightly below budget. Caught before it reached the owner report.

−15% vs budget

Northgate is down because its anchor closed

BigBox Mart (88,347 sq ft) left on 31 March. Occupancy fell from 97.9% to 72.0%, traffic is down 9% year over year, and sales have run about 15% below budget every month since.

Month-end data audit

Tenants submit their own sales, and door counters fail. Before any number goes to an owner, I run the same checks every month. These are the issues they caught this period and what each did to the totals.

The checks

  • Duplicates: more than one report for the same unit, tenant and month.
  • Spikes: a month above 5× the tenant's own 3-month average.
  • Missing reports: an open lease with no sales for the month.
  • Counter outages: zero visitors on a trading day.
  • Counter errors: traffic above 1.6× the median for that weekday over the surrounding 8 weeks.

What changed the story

Lease expiries in the next 12 months

Occupancy cost is annual base rent ÷ trailing 12-month sales. Above about 12–15%, a tenant may struggle to renew at the same rent.

How I built it

  1. Loaded the data into PostgreSQL — seven tables: properties, units, tenants, leases, monthly tenant sales, budget and daily traffic.
  2. Ran the validation checks in SQL before building anything, and logged each issue with its impact.
  3. Built the actual vs budget report in Excel on structured Tables, with one month input cell driving every formula.
  4. Modelled it in Power BI as a star schema with a date table, and wrote the variance, YoY and occupancy measures in DAX.
  5. Published this page with the corrected figures, plus a switch to show the numbers as originally reported.
SQL: catching the decimal slip 
WITH s AS (
  SELECT unit_id, tenant_id, sales_month, reported_sales,
         AVG(reported_sales) OVER (
           PARTITION BY unit_id, tenant_id
           ORDER BY sales_month
           ROWS BETWEEN 3 PRECEDING AND 1 PRECEDING
         ) AS trail_3m
  FROM tenant_sales
)
SELECT *, reported_sales / NULLIF(trail_3m, 0) AS ratio
FROM s
WHERE reported_sales > 5 * trail_3m;
SQL: open leases with no sales report 
SELECT l.unit_id, l.tenant_id
FROM leases l
LEFT JOIN tenant_sales s
  ON  s.unit_id = l.unit_id
  AND s.tenant_id = l.tenant_id
  AND s.sales_month = DATE '2026-09-01'
WHERE l.open_date <= DATE '2026-09-30'
  AND l.lease_end  >= DATE '2026-09-01'
  AND s.unit_id IS NULL;
Excel: actual vs budget for the selected month 
A4  =UNIQUE(Budget[property_id])
B4  =SUMIFS(Sales[reported_sales], Sales[property_id], A4#, Sales[sales_month], $B$1)
C4  =SUMIFS(Budget[budget_sales], Budget[property_id], A4#, Budget[sales_month], $B$1)
D4  =B4# - C4#
E4  =IFERROR(D4# / C4#, "")
DAX: variance and occupancy measures 
Actual Sales = SUM ( tenant_sales[reported_sales] )
Budget Sales = SUM ( budget[budget_sales] )
Variance %   = DIVIDE ( [Actual Sales] - [Budget Sales], [Budget Sales] )

Occupancy % =
VAR d = MAX ( 'Date'[Date] )
VAR occupied =
    SUMX (
        FILTER ( leases, leases[open_date] <= d && leases[lease_end] >= d ),
        RELATED ( units[gla_sqft] )
    )
RETURN DIVIDE ( occupied, SUM ( units[gla_sqft] ) )
